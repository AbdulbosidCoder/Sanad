# 4. Роли и права (RBAC)

## 4.1 Модель

- **Право (permission)** — атомарное действие: `orders.refund.approve`, `products.write`.
- **Роль** — набор прав. Роли бывают двух областей:
  - **platform** — сотрудники платформы (admin, support, finance, developer);
  - **store** — роли внутри конкретного магазина (owner, manager, staff), выдаются через `StoreMembership`.
- **Проверка в два шага** на каждом запросе бэкенда:
  1. *Есть ли право?* — зависимость FastAPI `require_permission("products.write")`.
  2. *Есть ли доступ к этому объекту?* — object-level проверка: товар принадлежит магазину, в котором пользователь состоит; заказ принадлежит покупателю и т. д. Ошибка возвращается как `404`, а не `403`, чтобы не раскрывать существование чужих объектов.
- Права кэшируются в Redis на пользователя и сбрасываются при изменении ролей.
- Фронтенд использует права только чтобы скрыть кнопки. Решение всегда принимает бэкенд.

## 4.2 Роли

| Роль | Область | Кто это |
|---|---|---|
| `guest` | — | Неавторизованный посетитель |
| `customer` | platform | Покупатель (выдаётся при регистрации) |
| `seller_owner` | store | Владелец магазина |
| `seller_manager` | store | Управляет товарами и заказами, не видит финансы и сотрудников |
| `seller_staff` | store | Обработка заказов и склад |
| `support_agent` | platform | Тикеты, просмотр заказов в рамках тикета |
| `support_lead` | platform | + назначение тикетов, эскалации, инициирование возврата |
| `finance` | platform | Транзакции, возвраты, сверки |
| `developer` | platform | Мониторинг, логи, фоновые задачи (без персональных данных) |
| `admin` | platform | Управление пользователями, магазинами, каталогом, настройками |
| `super_admin` | platform | Управление ролями и правами, опасные настройки. 1–2 человека |

## 4.4 Что пишется в журнал аудита (обязательно)

Вход сотрудника, смена ролей и прав, блокировка пользователя, приостановка магазина, одобрение продавца, ручное изменение статуса заказа сотрудником платформы, любые операции с возвратами и платежами, изменение комиссии, просмотр персональных данных покупателя сотрудником поддержки, изменение настроек платформы, экспорт данных.

## 4.5 Принципы

- **Минимальные права** по умолчанию; новая роль ничего не может, пока ей не выдали права.
- **Разделение обязанностей:** тот, кто инициировал возврат, не может сам его одобрить (проверяется в `refund.approve`).
- Developer **не видит** персональные данные: логи маскируются (email, телефон, адрес).
