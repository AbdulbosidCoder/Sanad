# 10. Пробелы в требованиях и ключевые решения

## 10.1 Чего не хватает в ТЗ

Для каждого пункта указано решение по умолчанию, которое принято в этом пакете. Любое можно поменять при согласовании.

| # | Вопрос | Решение по умолчанию | Влияние, если поменять |
|---|---|---|---|
| 1 | Как переводить описания товаров? | LLM-API за интерфейсом `Translator`; провайдер выбирается конфигом | Низкое: меняется один класс |
| 2 | Чем делать поиск? | PostgreSQL full-text + `pg_trgm` (опечатки) на старте; переход на Meilisearch, когда товаров станет больше ~100–200 тыс. | Низкое: модуль `search` за интерфейсом |
| 3 | Есть ли комиссия платформы и выплаты продавцам? | Комиссия в % на магазин и `LedgerEntry` закладываются в V1; сами выплаты — V2 | Среднее: без этого финансы придётся перестраивать |
| 4 | Кто доставляет и откуда трекинг? | Продавец сам меняет статусы и вводит трек-номер; интеграции со службами доставки — позже | Среднее: стоимость доставки в checkout |
| 5 | Как регистрируется продавец? | Заявка → проверка админом → магазин | Низкое |
| 6 | Валюта | Только UZS в V1, поле `currency` везде заложено | Низкое |
| 7 | Стоимость доставки | V1: фиксированная или бесплатная на магазин (настройка продавца) | Среднее |
| 8 | Налоги | Ставка НДС на товар (`tax_rate`), цены включают налог; фискальные чеки (ОФД) — вне V1 | Высокое, если чеки обязательны с запуска |
| 9 | Регистрация по телефону / SMS | V1: email + пароль, телефон опционально; SMS-OTP — после выбора SMS-провайдера | Среднее |
| 10 | Гостевой checkout | Нет: для заказа нужен аккаунт; гостевая корзина есть | Низкое |
| 11 | Модерация товаров | Пост-модерация: товар публикуется сразу, админ может скрыть | Низкое |
| 12 | Срок возврата | Настройка платформы, по умолчанию 14 дней | Низкое |
| 13 | Чат покупатель ↔ продавец | Не в V1 (только тикеты поддержки) | Среднее |
| 14 | Хранение персональных данных | Серверы в Узбекистане (закон о персональных данных требует локализации данных граждан РУз) — **нужно подтвердить хостинг** | Высокое для выбора облака |
| 15 | SEO | Покупательская витрина с SSR/ISR, мультиязычные URL `/uz/...`, `/ru/...`, `/en/...`, `hreflang` | Низкое |
| 16 | Объём на старте | Проектируем под ~10 тыс. товаров, ~1 тыс. заказов в день; масштабирование — вертикально + реплики чтения | Низкое |

## 10.2 Ключевые технические решения (ADR)

Каждое решение оформлено коротко. После согласования каждое принятое решение будет оформлено отдельным ADR в `docs/adr/`.

1. **Модульный монолит, а не микросервисы.** Одна команда, один деплой, транзакции в одной БД (критично для checkout и остатков). Границы модулей и outbox-события оставляют путь к выносу сервисов.
2. **PostgreSQL как единственный источник истины.** Redis только для кэша, rate limit, очередей и идемпотентности; потеря Redis не теряет данные.
3. **Родительский заказ + заказы продавцов.** Один платёж на весь checkout, но независимая обработка, статусы и возвраты по каждому продавцу.
4. **Статусы заказа и платежа раздельно.** Заказ может быть «отправлен», а платёж «частично возвращён»; смешивание статусов ломается на первом же частичном возврате.
5. **Резерв остатков атомарным UPDATE с условием**, без блокировок на уровне приложения; резерв с TTL.
6. **Transactional outbox** для событий: перевод, индексация, уведомления не теряются и не выполняются, если транзакция откатилась.
7. **JWT access + ротируемый refresh в HttpOnly cookie**, а не долгоживущий JWT: можно отозвать сессию и обнаружить кражу токена.
8. **Изоляция продавцов в два рубежа:** фильтр в репозитории + PostgreSQL RLS. Ошибка в одном слое не приводит к утечке.
9. **UUID v7** для идентификаторов: нельзя перебрать чужие ID, при этом индексы остаются эффективными.
10. **Переводы в отдельных таблицах** (`*_translation`) с пометкой `original | machine | manual`, а не JSON-поля: удобнее поиск, индексы и ручные правки.
11. **Фронтенд — монорепо с тремя приложениями и общей дизайн-системой**; клиент API генерируется из OpenAPI, поэтому контракт один для веба и будущих мобильных клиентов.
12. **Дизайн-система:** основной цвет forest-800 `#124929` (оттенок 145°), шкала forest-50…950, акценты emerald и sand, шрифты Manrope + Inter (оба с кириллицей и узбекской латиницей). Макет: https://claude.ai/artifact/88UWca9HczPSqwZn8XyYnM

## 10.3 Риски

- **Качество автоперевода** узбекского: проверить на реальных описаниях до запуска, дать продавцу удобную правку.
- **Интеграция Uzcard/Humo**: документация и тестовые среды выдаются после договора с процессингом; начать переговоры заранее.
- **Локализация данных**: выбор хостинга в Узбекистане влияет на доступность управляемых сервисов (managed PostgreSQL, S3).
- **Объём V1** большой для одного разработчика; при нехватке времени кандидаты на перенос в V1.1 — тренды, «просмотры без продаж», скидки по периодам.
