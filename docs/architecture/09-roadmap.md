# 9. Роадмап V1 / V2 / V3

Длительности указаны условно для одного full-stack разработчика с AI-ассистентом; их уточним после согласования. Каждый этап завершается рабочим функционалом, тестами и демо.

## V1 — веб-маркетплейс (desktop, tablet, mobile web)

| Этап | Содержание | Результат |
|---|---|---|
| **0. Фундамент** | Монорепо, Docker Compose, FastAPI-каркас с модулями, Alembic, Next.js-приложения, `packages/ui` с токенами дизайн-системы, i18n-каркас, CI (lint, typecheck, тесты, сборка образов), генерация API-клиента | `make up` поднимает всё, health-чеки зелёные |
| **1. Identity и RBAC** | Регистрация, вход, refresh-ротация, сессии, роли/права, object-level проверки, аудит, rate limit, смена языка | Вход во все три приложения с правильными правами |
| **2. Магазины и каталог** | Заявки продавцов, магазины, сотрудники, категории, бренды, товары, варианты, изображения (S3), склад, скидки | Продавец заводит товары, админ модерирует |
| **3. Переводы** | Абстракция `Translator`, автоперевод описаний, ручная правка, переводы категорий, словари UI на 3 языках | Товар, созданный на одном языке, доступен на трёх |
| **4. Витрина и поиск** | Главная, каталог, поиск (PostgreSQL FTS + trigram), фильтры, сортировки, автодополнение, карточка товара, избранное, история поиска, просмотры | Покупатель находит и смотрит товары |
| **5. Корзина, checkout, платежи** | Корзина (гость + слияние), checkout с разбиением по продавцам, резерв остатков, `PaymentProvider` + FakeProvider, вебхуки, идемпотентность, история и трекинг заказов | Полный цикл покупки на тестовых платежах |
| **6. Операции продавца** | Обработка заказов, статусы, отмены, возвраты, уведомления (in-app + email) | Продавец ведёт заказы до доставки |
| **7. Аналитика и рекомендации** | Агрегаты (продажи, выручка, просмотры, показы, конверсия, low-stock, «просмотры без продаж»), дашборд продавца, базовые рекомендации, хиты недели, тренды, отзывы | Дашборд продавца и персональная главная |
| **8. Админка, поддержка, финансы, тех. операции** | Пользователи, магазины, тикеты и переписка, транзакции, возвраты денег с разделением обязанностей, журнал аудита, health и фоновые задачи | Все внутренние роли работают в своей панели |
| **9. Укрепление и релиз** | Security-тесты (OWASP ZAP), нагрузочные тесты поиска и checkout (k6), бэкапы и восстановление, документация, prod-compose, staging | Готовность к запуску V1 |

## V2 — кросс-платформенные клиенты

- Мобильные приложения Android/iOS. **Рекомендация: React Native (Expo)** — переиспользует TypeScript, `api-client`, словари i18n и токены дизайн-системы из монорепо. Flutter даёт чуть лучшую производительность UI, но потребует дублировать клиент и словари на Dart.
- Десктоп Windows/Linux: **Tauri** поверх существующего веб-приложения (продавец и админка в первую очередь).
- Бэкенд: только **добавления** — push-уведомления (FCM/APNs) как новый канал `notifications`, deep links, поток refresh-токена без cookie. Существующие эндпоинты не меняются.
- Подключение реальных платёжных провайдеров (Uzcard, Humo, Visa) как новых классов `PaymentProvider` — можно сделать и раньше, независимо от V2.
- Выплаты продавцам (payouts) на основе `LedgerEntry`.

## V3 — продвинутая безопасность

- 2FA: TOTP, резервные коды; затем passkeys (WebAuthn) через `user_credentials`.
- Управление устройствами и сессиями в профиле, уведомления о новых входах.
- Детект подозрительных входов (новая страна/устройство, скорость перемещения, перебор).
- Антифрод заказов и платежей: скоринг (velocity-правила, совпадения устройств/адресов, аномальные суммы), ручная очередь проверки для финансов.
- Расширенный аудит: экспорт в SIEM, оповещения о чувствительных действиях.
- Обязательная 2FA для всех ролей платформы и владельцев магазинов.

## Точки расширения, заложенные в V1

| Будущая функция | Что уже есть в V1 |
|---|---|
| Мобильные/десктоп клиенты | API-first, OpenAPI-клиент, версия `/api/v1`, нет логики во фронте |
| Реальные платежи | `PaymentProvider`, вебхуки, идемпотентность, независимые статусы |
| Выплаты продавцам | `LedgerEntry`, `commission_rate` у магазина |
| Внешний поиск | Модуль `search` за интерфейсом, индексация по событиям |
| ML-рекомендации | Модуль `recommendations` за интерфейсом, сбор просмотров/поиска/покупок |
| 2FA / passkeys | `Session`, `user_credentials`, многошаговый вход, `require_sensitive_action()` |
| Вынос модуля в сервис | Границы модулей, outbox-события, запрет перекрёстных импортов |
